## Agent Brief

**Summary:** `variants` lists every string-literal-union prop a component declares, not only CVA ones.

**Current behavior:**
`variantProps` in `cli/component-index.mts` matches only the CVA declaration shape, which ends in `| null | undefined;`:
`/^\s*(\w+)\?:\s*((?:"[^"]*"\s*\|\s*)+)null\s*\|\s*undefined;/gm`.
Hand-written props such as `size?: "default" | "sm";` (on its own line in `card.d.ts`) do not end that way, so they are skipped.

**Desired behavior:**
Literal-union props are found whether or not the union ends in `null | undefined`. The result keeps today's shape, `Record<prop, string[]>`.

**Open question:** two different props with the same name in one file (sidebar has `size` in a CVA and `size?: "sm" | "md"` on another part) collapse into one key today (`??=` keeps the first). Either keep that or key by part; per-part output belongs to 04.

**Key interfaces:**
- `variantProps` in `cli/component-index.mts` and its tests in `cli/component-index.test.mts`.

**Acceptance criteria:**
- [x] `docs card` → `variants: { size: ["default", "sm"] }`.
- [x] `docs sheet` → `variants` includes `side: ["top", "right", "bottom", "left"]`.
- [x] `docs button` CVA variants are unchanged.
- [x] Unit tests cover the CVA shape, the plain union shape, and an inline intersection such as `React.ComponentProps<"div"> & { size?: "default" | "sm"; }`.

**Out of scope:**
- Non-literal prop types (issue 04).

## Resolution

`variantProps` matches any union of two or more string literals, on its own line or inline, with an optional `| null | undefined` tail. On a repeated prop name, a CVA union wins over a hand-written one, so sidebar keeps `variant: default|outline`. Old and new outputs were compared over every `dist` `.d.ts`: CVA values did not change, and the only differences are additions. Per-part props are covered in 04.
