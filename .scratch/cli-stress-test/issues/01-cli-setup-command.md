**Triage:** ready-for-agent

**Evidence:** 6/6 agents could not learn the CSS setup from the CLI.
- 2 agents (crm-dashboard, analytics-charts) never found `styles.css`. They wrote their own token set, `@theme inline` mapping and `@custom-variant dark` (57–66 lines).
- 3 agents guessed the import path by trial and error (`style.css`, `theme.css`, `globals.css`, `tailwind.css` all failed).

- Providers were also guessed: whether `TooltipProvider` is required, that `Toaster` must be mounted, that `SidebarProvider` is required (`useSidebar` throws without it, `sidebar.tsx:46`).

## Agent Brief

**Summary:** A new `earth-ui setup` command prints everything a package-mode consumer must do before using any component.

**Current behavior:**
The CLI has `list`, `search`, `docs`, `source`, `help`. None of them mention the package stylesheet, the import order, the dark-mode strategy, required providers or optional peer dependencies. That information lives in `styles.css` comments and the package README (lines 70–83 cover `Toaster`, sonner and `ThemeProvider`), which an agent using the CLI does not read.

**Desired behavior:**
`earth-ui setup` prints JSON (same contract as every other command) that covers:
- CSS: import `tailwindcss` first, then `<package>/styles.css`, as exact lines. State that the stylesheet already registers the package's built files as a Tailwind source (`styles.css` has `@source "./dist/**/*.js"`), so no `@source` line is needed, and that it imports `tw-animate-css`, which is a package dependency, so the consumer installs nothing for it.
- Dark mode: styles apply under a `.dark` class on an ancestor (usually `<html>`), per `@custom-variant dark (&:is(.dark *))`.
- Providers and mounted elements:
  - Candidates are derived from the Component Index: exports whose name ends in `Provider`.
  - Required vs optional, and elements that must be mounted, are a small hand-kept note: `SidebarProvider` required (`useSidebar` throws); toast `Toaster` and sonner `Toaster` must be mounted; `TooltipProvider` is optional (Base UI tooltips work without it; it only shares delay).
- Optional peer dependencies, derived from `package.json` `peerDependenciesMeta` crossed with each component's `dependencies` (same derivation as issue 02): `sonner` → `sonner`, `next-themes`; `use-highlighted-code` → `shiki`, with the install command.
- Package name and version, read from `package.json`, so the output matches the installed package.

`help` lists `setup`. `search` for setup words (`setup`, `css`, `theme`, `dark`, `tailwind`, `tokens`, `install`, `provider`) points to `setup` instead of returning `[]` or weak component matches. The pointer mechanism is shared with issues 05 and 07; build it once (see 07).

**Key interfaces:**
- The pure command functions in `cli/commands.mts`: add a `setup` function beside `list`/`search`/`docs`/`source`/`help`, so a future MCP server can wrap it too.
- The `COMMANDS` table in `cli/commands.mts` (drives `help`).
- `scripts/smoke-package.mts`.

**Acceptance criteria:**
- [x] `earth-ui setup` prints valid JSON with the CSS import lines, dark-mode rule, provider list and optional peer-dependency list.
- [x] A unit test asserts the output's package name and version equal `package.json`.
- [x] The provider list marks which entries are hand-kept, and `TooltipProvider` is listed as optional.
- [x] `scripts/smoke-package.mts` writes the throwaway app's `app.css` from the `setup` output (not a hard-coded string) and asserts the compiled CSS contains `--primary` in addition to the existing button sentinel class.
- [x] `earth-ui help` lists `setup`.
- [x] `earth-ui search css` and `earth-ui search "dark mode"` return a pointer to `setup`, in the shape defined by issue 07.
- [x] Unit tests cover the new command.

**Out of scope:**
- Writing files into the consumer project (`init` that edits `index.css`). Print only.
- Copy-mode (`shadcn add`) setup.

**Related:** 02 (same peer-dependency derivation), 05 and 07 (search pointer), 09 (`help` changes).

## Resolution

Added `setup(index, pkg)` in `cli/commands.mts` and the `setup` command. Providers come from index exports ending in `Provider`, merged with the hand-kept `PROVIDER_NOTES` table (`handKept: true`). Optional peers come from each entry's `install` crossed with `peerDependenciesMeta`. `scripts/smoke-package.mts` writes `app.css` from `setup.css.lines` after install and asserts `--primary`. Setup words point to `setup` through the `search` topics (07).
