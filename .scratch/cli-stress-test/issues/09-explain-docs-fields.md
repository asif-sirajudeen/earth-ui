# 09 — Explain `rootImport` and other `docs` fields

> *This was generated by AI during triage.*

**Category:** enhancement
**Triage:** ready-for-agent
**Status:** resolved (2026-11-11), uncommitted on branch `chore/main-audit-fixes`

**Evidence:** 5/6 agents reported `rootImport: true/false` as unexplained. `docs sonner` has `rootImport: false`; agents could not tell it means "not exported from the package root, import the subpath". All agents used subpath imports to be safe.

## Agent Brief

**Summary:** CLI output says what each `docs` field means.

**Current behavior:**
`docs` returns 12 fields: `name`, `type`, `title`, `description`, `import`, `rootImport`, `exports`, `variants`, `dependencies`, `links`, `baseUiDoc`, `props` (`source` is stripped on purpose; use the `source` command). `help` describes commands only (`name`, `usage`, `description`, `example`), not fields.

Field facts:
- `rootImport`: true when `dist/index.d.ts` re-exports the component. False today for `sonner` (subpath-only by design in `scripts/build-index.mts`) and the hooks `use-highlighted-code`, `use-mobile`. The `import` subpath always works.
- `links`: keys vary (`docs`, `examples`, `api`); hooks have `{}`.
- `baseUiDoc`: the Base UI doc slug, or null; `props` comes from it.
- `variants`: CVA variant props, or null.

**Desired behavior:**
`help` gets a `fields` object, built from a `FIELDS` const next to `COMMANDS` in `cli/commands.mts`, with one line per `docs` field. Field descriptions are not added to each `docs` response (03 wants smaller output). `rootImport` reads: "true: also exported from the package root. false: import only from the `import` subpath, for example `@asif-sirajudeen/earth-ui/sonner`."

Optional, from 10: `help`'s description says examples use the scoped `npx @asif-sirajudeen/earth-ui` because the unscoped `npx earth-ui` can run a different npm package, while `usage` lines show the bin name.

**Acceptance criteria:**
- [x] `help` output has a `fields` entry for every field `docs` returns.
- [x] The `rootImport` description says false means import only from the `import` subpath.
- [x] A unit test computes `Object.keys(docs(index, "dialog"))` and fails if any key has no `FIELDS` entry.
- [x] Fields added by other issues (02 `install`, 04 per-part props) get `FIELDS` entries in the same change that adds them.

**Out of scope:**
- Renaming fields.

**Related:** 05 also adds to `help` (`conventions`). Keep both as sibling keys in one `help` shape.

## Resolution

`FIELDS` lives next to `COMMANDS`, and `help` returns `fields` and `conventions`. A test fails if any `docs` key, default or `--full`, has no `FIELDS` entry. `keywords` is stripped from `docs` output, like `source`. The scoped-`npx` line from 10 is in the `help` description.
