# 07 — `search` misses use-case words and returns bare empty results

> *This was generated by AI during triage.*

**Category:** enhancement
**Triage:** ready-for-agent
**Status:** partially resolved (2026-11-11): topics and hint shipped; keywords removed by owner decision

**Evidence (verified):** `search stats`, `search stepper`, `search cart`, `search tokens`, `search tailwind`, `search quantity`, `search xyzzy` return `{ "components": [] }`. `search "image gallery"` returns only avatar. `search modal` returns alert-dialog first and dialog second, both score 1 (description-only hits; ties keep index order). Several agents read the 1s as "flat scoring"; the scorer is weighted (exact name 5, name substring 3, title 2, description 1, export 1), but use-case words only ever hit descriptions.

## Agent Brief

**Summary:** `search` finds components by common use-case words, points to non-component topics, and an empty result tells the user what to do next.

**Current behavior:**
Search scores tokens against name, title, description and export names only. No synonyms or keywords exist. An empty result is `{ "components": [] }` with no hint.

How metadata reaches the CLI: `registry/metadata.ts` → `scripts/build-registry.mts` → `registry.json` → `shadcn build` → `dist/registry/<name>.json` → Component Index. `ItemMetadata` in `scripts/registry-items.mts` is `{ title, description, meta? }`, and `deriveItems` copies only those plus derived fields, so a new top-level field would be dropped. `IndexRegistryItem` types only `meta.links`.

**Prerequisite:** `registry/metadata.ts` is deleted in the current working tree, and `scripts/build-registry.mts` imports it. Restore it before starting.

**Desired behavior:**
- Each registry entry can carry hand-written keywords in `meta.keywords` (consistent with `.out-of-scope/generated-metadata.md`: metadata is written by hand; `meta` avoids adding an unknown top-level field to the shadcn registry item). Keywords score above description hits (for example 4).
- Seed keywords for at least: modal → dialog; stats/metric/kpi → card; gallery/slider → carousel; notification → toast; dropdown → select; quantity → input-group; cart → drawer, sheet.
- `stepper`/`wizard` is an owner decision: earth-ui has no stepper, and pointing to `tabs` may mislead. Default: no keyword, so the empty-result hint applies.
- Topic pointers: `search` can return non-component topics (for example `{ "topics": [{ "name": "setup", "command": "earth-ui setup" }] }`) ranked above component hits. This one mechanism serves setup words (01) and `asChild`/`render` (05).
- An empty result adds a hint, for example `"hint": "No match. Run earth-ui list to see every component."`

**Key interfaces:**
- `ItemMetadata` and `deriveItems` in `scripts/registry-items.mts`; `IndexRegistryItem` and `ComponentEntry` in `cli/component-index.mts`.
- The `search` scoring function in `cli/commands.mts`.

**Acceptance criteria:**
- [ ] `deriveItems` carries `meta.keywords` into the built registry item (test in `scripts/registry-items.test.mts`), and the Component Index exposes it.
- [ ] `search modal` returns `dialog` first, because the keyword score beats the description score.
- [ ] `search stats` returns `card`.
- [x] `search xyzzy` returns an empty list plus a hint.
- [x] The topic-pointer shape is defined and tested; 01 and 05 use it.
- [ ] `docs <unknown>` suggestions benefit from keywords (it reuses `search`); a test covers one case.
- [ ] Unit tests cover keyword scoring and the empty hint. (Hint is covered; keyword scoring was removed with the feature.)

**Out of scope:**
- Fuzzy matching or embeddings.
- Generating keywords automatically.
- Name-substring false positives (`t.includes(c.name)` gives +3 for any query word containing a short component name).

## Resolution

Keywords (`meta.keywords`, +4 score, seeded for dialog, card, carousel, toast, sonner, select, input-group, drawer, sheet) were implemented and then removed at the owner's request (2026-11-11). Topics and the empty-result hint remain.

`search` always returns `{ topics, components }`, and adds a `hint` only when both are empty. Topics are `setup` and `conventions`. Unknown-name suggestions reuse `search`.
