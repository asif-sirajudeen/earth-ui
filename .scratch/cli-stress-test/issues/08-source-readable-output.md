# 08 — `source` code is hard to read as an escaped JSON string

> *This was generated by AI during triage.*

**Category:** enhancement
**Triage:** ready-for-human
**Status:** resolved (2026-11-11), uncommitted on branch `chore/main-audit-fixes`

**Evidence:** 4/6 agents piped `source` through python or grep to unescape `files[].code`. Agents also flagged that `@/components/...` imports in the source are internal aliases that are not valid consumer imports.

Verified: the largest `source` output is `sidebar` at about 23 KB; `source use-highlighted-code` is about 6 KB. (The 92 KB figure in the original report does not reproduce; large outputs are `docs`, see 03.) `cn` imports are not an alias: `cn` is a real npm package and a package dependency. Only `@/components/<x>` is internal.

## Agent Brief

**Summary:** `source` can print the code as plain text, and the output says how its internal imports map to package imports.

**Current behavior:**
`source` returns `{ name, import, files: [{ path, code }] }`, with code JSON-escaped. The `@/` mapping is explained nowhere a CLI user sees it: not in `help`, not in the `source` description, only in a code comment above `source()` in `cli/commands.mts`.

**Desired behavior:**
- A flag (for example `source <name> --raw`) prints the file contents as plain text. Multiple files are separated by a header line naming each path. Unknown names still print a JSON error on stderr and exit 1.
- The JSON output carries a field `importNote` mapping `@/components/<x>` to `<package>/<x>`.

**Why ready-for-human:** "Every command prints JSON" is a stated contract (README and `help`). A plain-text mode breaks it and needs an owner decision. If `--raw` is rejected, the `importNote` part still stands on its own and can be done by an agent.

**Key interfaces:**
- `source()` and `USAGE`/`COMMANDS` in `cli/commands.mts`; `parseArgs` options in `cli/earth-ui.mts`.

**Acceptance criteria:**
- [x] `source dialog --raw` prints the TSX with no JSON escaping, one header line per file.
- [x] `source <unknown> --raw` prints a JSON error on stderr and exits 1.
- [x] Default `source` output is unchanged except for the `importNote` field.
- [x] A unit test in `cli/commands.test.mts` covers `importNote`.
- [x] `help` documents the flag.

**Out of scope:**
- Rewriting imports in the printed source.

## Resolution

Owner decision: add `--raw`. `source` JSON gains `importNote`. `source <name> --raw` prints each file after a `// ==> <path>` header line. Errors stay JSON on stderr with exit code 1. JSON stays the default.
