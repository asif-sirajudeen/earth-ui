## Agent Brief

**Summary:** `docs` gives every component's exported parts a props summary, including parts that wrap third-party libraries and hooks.

**Current behavior:**
Props come only from the Base UI doc. `buildComponentIndex` already reads each component's built `.d.ts` (through the exports map) for `exportedNames` and `variantProps`, both regex parsers. Prop types and hook signatures are not surfaced.

What the `.d.ts` files contain:
- `card.d.ts`: `Card({ className, size, ...props }: React.ComponentProps<"div"> & { size?: "default" | "sm"; })`
- `sheet.d.ts`: `SheetContent(...: Dialog.Popup.Props & { side?: "top" | "right" | "bottom" | "left"; showCloseButton?: boolean; })`
- `calendar.d.ts`: `React.ComponentProps<typeof DayPicker> & {...}`, with `DayPicker` imported from `react-day-picker`
- `resizable.d.ts`: `ResizablePrimitive.GroupProps`, `PanelProps`, `SeparatorProps & { withHandle?: boolean }`, with `import * as ResizablePrimitive from "react-resizable-panels"`
- `use-mobile.d.ts`: `useIsMobile(): boolean`
- `use-highlighted-code.d.ts`: `useHighlightedCode(value: string, language: string)` returning a large expanded `ReactNode`-style union array

**Desired behavior:**
For every component, `docs` lists each exported part with its own props (the ones the component adds, such as `size`, `side`, `showCloseButton`, `withHandle`) and names the underlying props type it forwards (for example "Base UI Dialog.Popup", "react-day-picker DayPicker", "react-resizable-panels Panel"). Hooks list their parameters and return type. Data comes from the built type declarations, not hand-kept text. For Base UI backed components such as `sheet`, these own props appear alongside the Base UI reference.

**Decisions needed before work starts:**
1. Shape: shared with 03 (one `props` shape), or a separate field such as `parts` that leaves `props` to 03.
2. Parser location: `typescript` is only a devDependency, and the CLI ships in the package. Do not add it to `dependencies`. Either parse at build time in `scripts/` and ship JSON, or keep regex in the CLI and fall back to printing the declaration line verbatim.
3. Hook return types: print the declaration as written, or simplify (for example to `ReactNode[]`).

**Key interfaces:**
- `buildComponentIndex` / `ComponentEntry` in `cli/component-index.mts`.
- `exportedNames` / `variantProps` — existing `.d.ts` parsers to extend or sit beside.
- `cli/commands.test.mts`, which asserts `calendar` props is null and will change.

**Acceptance criteria:**
- [x] `docs card` lists `Card`'s `size` prop with values `"default" | "sm"`.
- [x] `docs sheet` lists `side` and `showCloseButton` on `SheetContent`, in addition to the Base UI reference it returns today.

- [x] A test iterates every `list` entry and asserts a non-empty per-part props result, except an explicit allow-list of entries with no props.
- [x] Unit tests cover the `.d.ts` parsing with fixtures taken from the card, sheet, calendar, resizable and use-mobile declarations above.
- [x] No new runtime dependency is added to the package.

**Out of scope:**
- Copying third-party library docs (react-day-picker, recharts) into the output. Name the type only.
- Reshaping Base UI props (issue 03).

**Related:** 12 (`variantProps` misses `Card` `size`).

## Resolution

Decisions:
- One `props` shape shared with 03.
- Parsing runs at build time. `scripts/build-props.mts` uses the TypeScript compiler API over `dist/**/*.d.ts` and writes `dist/props.json`, so the package gains no runtime dependency.
- Hook return types are printed as written.

Each part lists `forwards` (for example `react-day-picker DayPicker`, `react-resizable-panels SeparatorProps`, `@base-ui/react/dialog Dialog.Popup.Props`) and the props it adds. Hooks list `params` and `returns`. The allow-list for "no props" is `["direction"]`, because it only re-exports Base UI's DirectionProvider.
