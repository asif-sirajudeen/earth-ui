# 05 — State the `render` prop convention (no `asChild`)

> *This was generated by AI during triage.*

**Category:** enhancement
**Triage:** ready-for-agent
**Status:** resolved (2026-11-11), uncommitted on branch `chore/main-audit-fixes`

**Evidence:** 6/6 agents learned that triggers take `render={<Button />}` instead of shadcn's `asChild` only by reading `source`. They then guessed it for `PopoverTrigger`, `TooltipTrigger`, `AlertDialogTrigger`, `CollapsibleTrigger`, `DrawerTrigger`, `HoverCardTrigger` and `ContextMenuTrigger`. Agents trained on shadcn default to `asChild`, which does not exist here (no `asChild` anywhere in `src/` or `dist/components`).

Verified: `search aschild` and `search render` return `[]`; `search "as child"` returns unrelated hits (toast, aspect-ratio).

## Agent Brief

**Summary:** CLI output states, in one place, that parts compose through Base UI's `render` prop and that there is no `asChild`.

**Current behavior:**
No command states the convention. The `render` prop is present, but only as one row in each part's table inside the large `docs` `props` string (for example under `### Trigger` in `docs dialog`). Agents did not find it there. `DialogTrigger` and similar parts are typed as `DialogPrimitive.Trigger.Props`, so their source does not show `render` either.

**Desired behavior:**
- `help` includes a short `conventions` section: "Compose parts with `render={<Element />}` (Base UI). There is no `asChild`." It lives in `help`, which already ships, so this issue does not depend on 01. `setup` (01) may repeat it.
- `search` for `aschild`, `as child` or `render` points to the conventions text, using the pointer mechanism from 07, and the pointer ranks above component hits.

**Key interfaces:**
- `help()` and `COMMANDS` in `cli/commands.mts`.
- The `search` pointer mechanism (07).

**Acceptance criteria:**
- [x] `help` output has a `conventions` entry that names `render={<Element />}` and says there is no `asChild`.
- [x] `search aschild`, `search "as child"` and `search render` return the conventions pointer first.
- [x] Unit tests cover both.

**Out of scope:**
- Adding `asChild` support to components.
- A per-part "accepts render" flag in `docs`. The Base UI reference already lists `render`; making it prominent belongs to the props reshaping in 03.

**Related:** 07 (search pointer), 09 (`help` changes; combine `fields` and `conventions` in one `help` shape).

## Resolution

`help` has a `conventions` entry. `search` has a `conventions` topic, matched on `aschild` and `render`, and on the query with spaces removed so `"as child"` also matches. `setup` repeats the convention. `baseUi.common` in `docs` restates it.
