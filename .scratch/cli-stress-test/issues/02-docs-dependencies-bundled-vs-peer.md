## Agent Brief

**Summary:** `docs` tells a consumer which of a component's dependencies they must install themselves.

**Current behavior:**
The `dependencies` field of a Component Index entry is the registry item's dependency list (`name@range`, from `scripts/derive-deps.mts`). It mixes libraries the npm package already depends on with optional peer dependencies the consumer must add. For copy mode this list is correct; for package mode it misleads. This is working as designed for copy mode, hence enhancement, not bug.

**Desired behavior:**
`docs <name>` keeps `dependencies` unchanged and adds a field `install`: the packages the consumer must add for this component, as `name@range` with the range taken from `peerDependencies`. Rule: strip the range from each `dependencies` entry; keep it only if the name is in `peerDependencies`. Anything in package `dependencies` ships with the package and is dropped. `react`, `react-dom` and `tailwindcss` are already filtered out of item dependencies, so they never appear. Empty array when nothing is needed.

**Key interfaces:**
- `ComponentEntry` in `cli/component-index.mts` — add `install: string[]`.
- `IndexPackageJson` — today carries only `name`, `version`, `exports`. Add `dependencies`, `peerDependencies` and `peerDependenciesMeta`.

**Acceptance criteria:**
- [x] `docs dialog` → `install: []`.
- [x] `docs sonner` → `install: ["next-themes@~0.4.6", "sonner@^2.0.8"]` (ranges as in `peerDependencies`). `lucide-react` is not listed.
- [x] `docs use-highlighted-code` → `install: ["shiki@^4.6.0"]`.
- [x] `docs chart` → `install: []` (recharts is a package dependency).
- [x] `dependencies` output is unchanged for every component.
- [x] The field is derived from `package.json`, not hand-kept. A unit test covers it with a fixture that includes a dependency, an optional peer and a non-optional peer.

**Out of scope:**
- Changing the registry items or copy-mode dependency lists.

**Related:** 01 reuses this derivation for its optional peer-dependency list. 09 must describe the new field.

## Resolution

Added `installList(deps, pkg)` in `cli/component-index.mts` and `ComponentEntry.install`. It splits each entry on the last `@` and keeps peer dependencies only, with the range from `peerDependencies`. `IndexPackageJson` carries `dependencies`, `peerDependencies` and `peerDependenciesMeta`. Verified: `sonner` gives `["next-themes@~0.4.6", "sonner@^2.0.8"]`; `dialog` and `chart` give `[]`; `use-highlighted-code` gives `["shiki@^4.6.0"]`.
