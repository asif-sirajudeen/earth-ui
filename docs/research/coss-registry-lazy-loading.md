# Research: What "lazy loading" means in the coss ui registry approach

As of: 2026-11-09

## Summary

The lazy loading is a generated file, `apps/ui/registry/__index__.tsx`. It maps each item name to `React.lazy(() => import("@/registry/default/..."))`. It is consumed only by the docs site, to render live component previews. It never reaches `registry.json` or `public/r/*.json`, so it has no effect on what `shadcn add` consumers receive.

Evidence:
- The coss and Magic UI build scripts write `__index__.tsx` first. Then they write `registry.json`. Then they run `shadcn build`. The three steps are independent, and `shadcn build` reads only `registry.json` and the source files it lists.
- The built `public/r/button.json` and `public/r/registry.json` contain no `lazy` string (`grep -c lazy` returned 0 for both).
- `packages/shadcn/src` and `packages/registry/src` contain no reference to `__index__` or `__registry__` (the only `React.lazy` hits are test fixtures).
- Every `__index__` importer in coss is a docs-site file (`component-preview.tsx`, `lib/registry.ts`, `app/particles/*`).
- The official docs page https://ui.shadcn.com/docs/registry/getting-started does not mention lazy loading or `__index__`.

There is no "lazy loaded registry file". The registry JSON is a static file and is fetched whole, per item.

The same index exists in Magic UI, Cult UI, shadcn/ui, Plate, Supabase UI, Intent UI and legacy Animate UI v1. ReUI has a similar lazy preview loader. Kibo, neobrutalism and Animate UI v2 do not use a generated lazy index.

For earth-ui: the index is useful only if there is a docs or preview site that renders components by name. earth-ui has no docs site, so replicating it would produce a file that nothing consumes (inference from the facts supplied by the user).

## 1. Where the lazy loading is, in coss ui and Magic UI

### coss ui

**File.** `apps/ui/registry/__index__.tsx` (10,943 lines, 600 `React.lazy` entries). It is committed: `git check-ignore` matched nothing, and `git ls-files` lists it. Its header says it is autogenerated.

```tsx
// This file is autogenerated by scripts/build-registry.ts
// Do not edit this file directly.
import * as React from "react"

export const Index: Record<string, any> = {
  "accordion": {
    ...
    files: [{ path: "registry/default/ui/accordion.tsx", type: "registry:ui", target: "" }],
    component: React.lazy(async () => {
      const mod = await import("@/registry/default/ui/accordion.tsx")
      const exportName = Object.keys(mod).find(key => typeof mod[key] === 'function' || typeof mod[key] === 'object') || item.name
      return { default: mod.default || mod[exportName] }
    }),
```

### shadcn/ui itself (origin of the pattern)

shadcn's own build script documents why the lazy map exists and how it was split:

```
// Emits the React.lazy() expression used in the generated __components__ files.
// Components live in their own index, separate from registry metadata, so that
// metadata-only consumers (docs, registry JSON, llm/md routes) don't pull all
// component dynamic imports into their module graph — which previously inflated
// dev-server memory.
```
([build-registry.mts L248-L257](https://github.com/shadcn-ui/ui/blob/8ab27715521cbd4f87ae6886cd989cbb678f6de7/apps/v4/scripts/build-registry.mts#L248-L257))

shadcn now writes metadata to `registry/__index__.tsx` (no `React.lazy`, imports `server-only`) and the lazy entries to sharded `registry/__components__/<style>.tsx` files ([L268-L300](https://github.com/shadcn-ui/ui/blob/8ab27715521cbd4f87ae6886cd989cbb678f6de7/apps/v4/scripts/build-registry.mts#L268-L300), [L1334-L1345](https://github.com/shadcn-ui/ui/blob/8ab27715521cbd4f87ae6886cd989cbb678f6de7/apps/v4/scripts/build-registry.mts#L1334-L1345)). The script header lists `registry/__index__.tsx` and `examples/__index__.tsx` as "Persistent outputs" next to `public/r/*`, as separate outputs ([L28-L62](https://github.com/shadcn-ui/ui/blob/8ab27715521cbd4f87ae6886cd989cbb678f6de7/apps/v4/scripts/build-registry.mts#L28-L62)). coss and Magic UI still use the older single-file form.

## 4. What earth-ui would need to replicate it

Facts used (from the task brief, not re-verified here): no docs site, npm package built from `src/` with tsdown, `registry/{index.ts,registry-ui.ts,registry-hooks.ts,registry-styles.ts}`, `scripts/build-registry.mts` derives deps from imports and writes `registry.json`, then `shadcn build` writes `public/r`.

**Plainly: the lazy index is only useful with a docs or preview site.** The sole consumers found in every repo are preview components that render `<Index[name].component />`. Without such a site, a generated `__index__.tsx` has no importer. It does not change `registry.json`, `public/r/*.json`, or what `shadcn add` installs.

What replicating it would take (inference from the coss and Magic UI generators):
1. Add a step to `scripts/build-registry.mts` that loops over `registry.items`, skips items with no `files`, and writes `registry/__index__.tsx` with one `React.lazy(() => import("@/registry/..."))` per item. coss and Magic UI each use about 50 lines for this.
2. Keep it out of the registry: do not list it as an item file, and do not feed it to `shadcn build`.
3. Decide whether to commit it. coss, Magic UI and shadcn commit it. Intent UI and ReUI gitignore it.
4. Have a consumer. This means a docs app (or Storybook-like page) with a `ComponentPreview` that looks up `Index[name]`.
5. Path alias: the import specifier `@/registry/...` must resolve in the consumer app. earth-ui's current layout (source in `src/`, registry metadata in `registry/`) may need a different specifier. This is unverified.

Related things coss does that need no docs site, and may be what the user actually wants (inference only, not confirmed with the user):
- `registry.json` and `public/r` committed and regenerated by one script (earth-ui already does this).
- A drift check in CI (Magic UI `registry-drift` job).
- A dependency validator (`validate-registry-deps.mts`). earth-ui derives deps from imports already, which is stronger.
- A `registry -> package` sync (`sync-ui.mts`). earth-ui's source of truth is `src/`, so it is the reverse direction.

## Not found / unverified

- **Not found: any lazy-loading of registry JSON.** No surveyed repo lazy-loads `registry.json` or `public/r/*.json`. The shadcn CLI fetches an item's JSON directly.
- **shadcn docs.** The official page https://ui.shadcn.com/docs/registry/getting-started has no mention of lazy loading or `__index__`. It also does not say outright that item JSON includes file content. That was confirmed from `build.ts` source instead.
- **CLI consumer side.** I read `build.ts` only. I did not trace the `add` command's fetch code beyond a grep for `__index__`, `React.lazy` and `__registry__` in `packages/shadcn/src` and `packages/registry/src`, which found no implementation use.
- **Lineage of the coss and Magic UI generators.** The near-identical code suggests a common origin (shadcn's older `build-registry.mts`). I did not check git history.
- **Cult UI `__registry__/index.tsx`.** The generator was not found. It may be stale or hand-maintained.
- **shadcn/ui docs consumers.** I confirmed the files and generator, but did not trace each docs route that imports `__components__`.
- **Animate UI v2 registry build.** Not re-examined. Only the preview mechanism was checked.
- **Magic UI `@magicuidesign/cli`.** Not inspected.
- **Aceternity UI, Tremor.** Not checked.
- **Kibo, neobrutalism.** "No" means no lazy index was found by grep. Other preview mechanisms were not fully traced.
- **earth-ui facts.** Taken from the task brief. earth-ui files were not read.
- **Whether `shadcn build` would pick up `__index__.tsx` if listed.** Not tested (nothing was run). It is simply never listed.
